# Navigation Route Editor — Тестовое задание

## 1. Назначение
Цель инструмента — упростить и ускорить создание и редактирование навигационных маршрутов в Unity.

Сейчас точки маршрута создаются вручную в сцене, после чего добавляются в список `RouteController` через Inspector.

Для небольшого количества точек этого достаточно, но при создании больших маршрутов ручная настройка становится медленной и повышает вероятность ошибок.

`Route Editor` должен позволять дизайнеру создавать, редактировать и проверять маршруты непосредственно через отдельное окно Unity Editor и Scene View.

## 2. Основной рабочий процесс
Инструмент должен быть доступен через меню Unity Editor:

`Tools → Route Editor`

Пользователь выбирает существующий `RouteController` или создаёт новый маршрут.

Редактор отображает все точки маршрута в текущем порядке.

Пример:

Main Route

1. Start
2. Station
3. Pier
4. Mountain

Пользователь должен иметь возможность:

- создавать новую точку маршрута;
- удалять существующую точку;
- переименовывать точку;
- изменять порядок точек;
- выбирать точку в Scene View;
- перемещать точки стандартными средствами Transform в Unity;
- автоматически размещать точку на поверхности;
- визуализировать соединения между последовательными точками.

## 3. Создание точки маршрута
При создании новой точки инструмент автоматически создаёт `GameObject`, содержащий:

- компонент `RoutePoint`;
- trigger collider;
- visual marker;
- стандартное имя точки.

Новая точка автоматически добавляется в выбранный `RouteController`.

Пользователь не должен вручную добавлять созданную точку в список маршрута.

При необходимости инструмент может создавать новую точку в позиции Scene View cursor либо рядом с выбранной точкой маршрута.

## 4. Редактирование маршрута
Редактор должен отображать точки маршрута в виде упорядоченного списка.

Пользователь должен иметь возможность изменять порядок точек с помощью drag-and-drop либо кнопок `Up / Down`.

Изменение порядка точек в редакторе должно автоматически обновлять список маршрута в `RouteController`.

При выборе точки маршрута в редакторе соответствующий `GameObject` также должен выделяться в Unity Hierarchy и Scene View.

Удаление точки через Route Editor должно обновлять список `RouteController` и не оставлять `null` reference в маршруте.

## 5. Визуализация в Scene View
Инструмент должен визуализировать маршрут непосредственно в Scene View.

Для каждой точки маршрута должны отображаться:

- индекс точки в маршруте;
- её имя;
- marker;
- линия до следующей точки маршрута.

Пример:

[1 Start] -------- [2 Station] -------- [3 Pier] -------- [4 Mountain]

Эта визуализация должна существовать только в Editor и не должна отображаться в финальной игре.

При изменении положения точки линии и подписи должны обновляться автоматически.

## 6. Настраиваемые параметры
Инструмент должен позволять пользователю настраивать:

- имя точки;
- радиус или размер trigger collider;
- `marker prefab`;
- высоту marker;
- порядок точек маршрута;
- параметр `Snap To Ground`;
- отображение маршрута в Scene View.

Значения по умолчанию могут храниться в настройках Editor-инструмента.

### Snap To Ground

При использовании `Snap To Ground` инструмент выполняет raycast вниз от выбранной точки и перемещает её на найденную поверхность.

Если поверхность не найдена, положение точки не изменяется, а пользователь получает сообщение о том, что операция не была выполнена.

## 7. Проверка маршрута
Редактор должен содержать действие `Validate Route`.

Система проверки должна выявлять распространённые ошибки конфигурации, включая:

- маршрут не содержит точек;
- маршрут содержит только одну точку;
- наличие `null` references в списке маршрута;
- дублирующиеся точки маршрута (одинаковая позиция/название);
- отсутствие компонента `RoutePoint`;
- отсутствие trigger collider;
- collider не настроен как trigger;
- отсутствие visual marker;
- несколько точек находятся практически в одной и той же позиции (в радиусе 2-5 метров).

Обнаруженные проблемы должны отображаться в `Route Editor` с описанием ошибки и указанием затронутой точки.

Проверка не должна автоматически изменять маршрут, если пользователь явно не выбрал действие исправления.

## 8. Ожидаемый результат
После настройки маршрута пользователь получает готовую последовательность точек, автоматически назначенную в `RouteController`.

Runtime-система навигации не должна зависеть от того, каким способом были созданы точки маршрута.

Итоговый маршрут должен оставаться совместимым с существующей runtime-системой:

`RouteController → RoutePoint[]`

После настройки пользователь может сразу запустить сцену в `Play Mode` и протестировать маршрут.

## 9. Преимущества
Инструмент должен уменьшить количество повторяющихся ручных действий и снизить вероятность ошибок при настройке маршрутов.

Он позволяет дизайнеру создавать и изменять маршруты через Scene View без необходимости редактировать исходный код.

При этом runtime-реализация навигации остаётся простой, а процесс создания маршрутов становится быстрее и удобнее.
